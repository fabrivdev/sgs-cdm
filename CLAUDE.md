## Architecture

**Stack:** React 18 + TypeScript SPA with Supabase (PostgreSQL + Auth + Edge Functions) as backend.

**Key libraries:** React Router 6, TanStack React Query 5 (server state), React Hook Form + Zod (forms), TailwindCSS 3 + shadcn/ui (UI), Recharts (charts), date-fns 3, Supabase JS v2.

**Path alias:** `@/*` maps to `src/*`.

### Routing & Auth (`src/App.tsx`, `src/hooks/useAuth.tsx`)

All routes except `/auth` are wrapped in `<ProtectedRoute>`. The auth context (`useAuth`) provides:
- Session from Supabase Auth (email/password, persisted in localStorage)
- User profile from `profiles` table
- Roles from `user_roles` table — roles are `admin`, `cabecilla`, `tecnico`
- Super-admin check: hardcoded email `fabrizio.vega@cdm.com.py`

Admin-only routes: `/dashboard`, `/parque-clientes`, `/admin`.

### Data Layer

All Supabase queries go through the client at `src/integrations/supabase/client.ts`. TypeScript types for every table and view are auto-generated in `src/integrations/supabase/types.ts` — do not edit this file manually.

Server state is managed with **React Query**; prefer using `useQuery`/`useMutation` hooks rather than calling Supabase directly inside components. **Important Supabase v2 rule:** always call `.select()` before applying `.filter()`/`.gte()`/`.lte()` — the reverse order silently drops filters.

### Domain Logic (`src/lib/`)

- `constants.ts` — `SUCURSALES`, `MARCAS`, `ROLES` enums used app-wide
- `trabajos.ts` — job status transitions and display helpers
- `facturacionReglas.ts` — billing classification rules (controls which items appear in Dashboard KPIs)
- `trabajo-derivado.ts` — computed fields for work orders

### UI Conventions

- shadcn/ui primitives are in `src/components/ui/` — extend these rather than adding new ones
- Primary brand color: olive green `#86a536`; CLAAS/HORSCH have distinct brand colors defined in `tailwind.config.ts`
- Toast notifications via `sonner` — use `toast.success/error` from `src/hooks/use-toast.ts`
- `cn()` utility from `src/lib/utils.ts` for conditional Tailwind classes

### Supabase Edge Functions

Admin user operations (create/delete/list/update) are handled via Edge Functions in `supabase/functions/` because they require service-role access. Call these through the Supabase Functions client, not the regular REST API.

### TypeScript Config

`strictNullChecks` and `noImplicitAny` are both `false`. Do not introduce TypeScript strict-mode patterns that would conflict with the existing loose config.
